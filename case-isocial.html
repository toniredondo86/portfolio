Fundació iSocial

DESIGN SYSTEM ESCALABILIDAD ACCESIBILIDAD

Dos apps para un mismo ecosistema. Dos perfiles que no podrían ser más distintos.

iSocial reúne dos productos con necesidades opuestas: Nidus, una app orientada a personas en situación de exclusión social, e iSocialPro, una plataforma para trabajadores sociales centrada en la gestión de casos, documentación y comunicación.

El desafío no estaba en diseñarlos como si fueran uno solo, sino en construir un sistema capaz de conectar ambos sin borrar las diferencias que cada contexto exigía.

DURACIÓN

6 meses · 2023

ALCANCE

Nidus e iSocialPro

ROL

Lead Product Designer

PUNTO DE PARTIDA

La identidad existía. El sistema de diseño, no

El proyecto partía de referencias visuales ya definidas en ambos productos. iSocial contaba con una web corporativa consolidada y NIDUS tenía un branding inicial propio, pero en ninguno de los dos casos existía una estructura de diseño preparada para producto digital. El trabajo consistió en transformar esas bases visuales en un sistema coherente y escalable para dos productos con necesidades muy distintas.

Nidus

Usuarios finales

Una app para personas en situación de exclusión social. Un lugar donde guardar documentos importantes, compartirlos con los profesionales que les acompañan y mantener el contacto con los servicios de apoyo. Diseñarla bien significaba que cualquier persona pudiera usarla, independientemente de su experiencia con la tecnología.

PRINCIPIOS DEL SISTEMA

Los criterios que guiaron cada decisión

Diseñar para dos productos a la vez obliga a tomar partido desde el principio. Estos principios no surgieron de un ejercicio teórico, sino de las restricciones reales del proyecto.

  • 01

    Accesibilidad como punto de partida

    La accesibilidad no se trató como una capa posterior. Contraste, jerarquía, tamaño de texto y estados visibles se definieron desde el inicio para garantizar una experiencia clara y usable para cualquier perfil de usuario.

  • 02

    Coherencia sin hacer todo igual

    Ambos productos debían compartir una misma lógica de interacción, pero sin imponer la misma expresión visual ni el mismo nivel de complejidad. El sistema tenía que resultar reconocible en ambos contextos sin volverse idéntico.

  • 03

    Claridad por encima de expresión

    Las acciones más importantes debían reconocerse de un vistazo. En este contexto, el sistema priorizó comprensión inmediata, jerarquía clara y lectura rápida por encima de cualquier gesto visual innecesario.

  • 04

    Eficiencia donde la gestión lo exige

    El sistema debía adaptarse a distintos niveles de densidad de información según el contexto de uso, permitiendo recorridos más directos y eficientes sin perder orden ni legibilidad.

FOUNDATIONS

Una estructura compartida para dos productos

Reglas, criterios y decisiones daban coherencia al sistema y permitían adaptarlo a ambos productos. Más que una colección de estilos, era una lógica compartida preparada para sostener necesidades de uso distintas.

DECISIONES DE SISTEMA

Las decisiones que hicieron posible la coherencia

No se trataba de definir una capa visual común, sino de construir principios de interfaz que pudieran adaptarse sin romper la consistencia del ecosistema.

  1. Decisión 01

    Convertir marca en interfaz

    El punto de partida no era un sistema, sino activos de marca sueltos. El primer paso consistió en traducir logos, paletas y referencias visuales en foundations reales: color, tipografía, espaciado, jerarquías y reglas básicas de composición aplicables a producto digital.

  2. Decisión 02

    Coherencia sin uniformidad

    NIDUS e iSocialPro no podían compartir la misma expresión visual ni el mismo grado de complejidad. El sistema se diseñó para permitir variaciones en tono, densidad, componentes y jerarquía sin perder una base común de comportamiento y estructura.

  3. Decisión 03

    Diseñar para escalar

    Más allá de resolver pantallas concretas, el sistema se construyó para acelerar nuevas funcionalidades, facilitar consistencia entre productos y reducir la dependencia de decisiones puntuales. Cada componente debía ser útil en el presente y sostenible en el crecimiento futuro del ecosistema.

IMPACTO

Lo que el sistema hizo posible

El design system no fue solo una entrega técnica. Transformó la forma en que el equipo toma decisiones de diseño y abrió la puerta a un crecimiento más consistente del ecosistema.

  • Base compartida para el equipo

    Por primera vez, todos los productos del ecosistema parten del mismo lenguaje. Tokens, componentes y patrones son reutilizables entre plataformas.

  • Mayor consistencia entre productos

    Las interfaces de NIDUS e iSocialPro comparten una coherencia visual y estructural que antes no existía.

  • Diseño más rápido

    Los flujos nuevos ya no parten de cero. El sistema acelera las decisiones y reduce el tiempo de definición visual en nuevas funcionalidades.

  • Escalabilidad para nuevos productos

    El sistema fue construido para absorber la evolución del ecosistema. Nuevas plataformas pueden incorporarse sin redefinir las bases.

  • Accesibilidad como condición estructural

    La accesibilidad dejó de ser un criterio puntual para convertirse en una condición integrada desde las bases del sistema.

REFLEXIÓN

Un sistema no impone orden visual. Crea una base para tomar mejores decisiones.

Este proyecto me obligó a entender que la coherencia no consiste en repetir componentes, sino en definir principios suficientemente sólidos como para adaptarse a realidades distintas.

Diseñar para un ecosistema social implica trabajar con restricciones reales, perfiles vulnerables y contextos donde la claridad y la accesibilidad no son un valor añadido, sino una necesidad estructural.

La diferencia entre diseñar pantallas y diseñar sistemas es que un sistema te obliga a pensar en consecuencias: qué pasa cuando escala, cuando cambia el equipo, cuando aparece un nuevo producto. El resultado no fue solo una librería de UI, sino una forma de diseñar con más consistencia, más criterio y más capacidad de crecimiento.
