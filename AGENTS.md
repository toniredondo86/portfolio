# AGENTS.md

## Mission

Build and maintain a premium portfolio website for Toni Redondo, UX Designer.

The portfolio must communicate:

- clarity
- credibility
- professional maturity
- strong UX thinking
- real-world impact

The experience should feel:

- visually calm
- easy to scan
- intentional
- polished
- responsive

---

## Main goals

1. Communicate Toni’s value clearly in the first seconds
2. Show strong UX thinking through real case studies
3. Demonstrate impact, constraints, and decision-making
4. Maintain a clean, modern, and lightweight interface
5. Ensure the site feels solid on desktop and mobile

---

## Audience

Primary audience:

- hiring managers
- product design leaders
- recruiters
- international clients

They should quickly understand:

- what Toni does
- how he thinks
- what kind of projects he has worked on
- what outcomes he helped achieve
- why he is credible

---

## Core principles

- clarity over decoration
- evidence over claims
- decisions over generic process
- outcomes over tasks
- consistency over experimentation

Avoid anything that makes the portfolio feel:

- unfinished
- overly animated
- vague
- crowded
- template-like

---

## Required sections

- Hero
- Selected Work
- Case Studies
- About
- Contact

Optional sections only if they add real value:

- Testimonials
- Experience snapshot
- Tools only when relevant to the narrative

Do not add sections just to fill space.

---

## Writing rules

- write in concise English
- use short paragraphs
- avoid filler and UX clichés
- avoid generic claims like “user-centered” unless supported
- explain what changed and why
- describe trade-offs and constraints
- highlight outcomes with evidence whenever possible
- keep the tone professional, direct, and calm

Preferred writing style:

- specific
- grounded
- credible
- easy to scan

Avoid:

- buzzwords
- exaggerated language
- long introductions
- repetitive explanations
- vague impact statements

---

## Home page rules

The homepage must answer these questions quickly:

1. Who is Toni?
2. What kind of UX work does he do?
3. Which projects prove it?
4. Why should someone keep reading?

Hero section must:

- state clearly that Toni is a UX Designer
- communicate his value in one clear sentence
- avoid long paragraphs
- include a real and functional CTA

Selected Work must:

- show real project thumbnails
- avoid placeholders or lorem ipsum
- use consistent card structure
- make each case study feel distinct
- include a short description focused on context, challenge, or outcome

---

## Case study structure

Every case study must follow this order:

1. Context
2. Problem
3. Role
4. Process
5. Key decisions
6. Outcome
7. Learnings

Each section must have a clear purpose:

### 1. Context

Explain the product, company, or environment.
Give enough background to understand the project.

### 2. Problem

Describe the actual challenge.
Focus on the user, business, or operational problem.

### 3. Role

Clarify Toni’s contribution.
Be explicit about ownership, collaboration, and scope.

### 4. Process

Show the path taken.
Keep it concise and focused on relevant steps only.

### 5. Key decisions

Explain the important UX choices.
Show reasoning, priorities, and trade-offs.

### 6. Outcome

Show impact.
Use metrics, behavioural improvements, adoption, efficiency gains, or measurable results whenever possible.

### 7. Learnings

Show reflection and maturity.
State what the project taught and how it shaped future decisions.

---

## Case study quality rules

Case studies must:

- reflect real work
- avoid “coming soon” style sections
- avoid unfinished placeholders
- include project constraints
- show decision-making, not just deliverables
- demonstrate why the work mattered

When possible, include:

- before/after comparisons
- scale of usage
- complexity of the environment
- stakeholders involved
- measurable outcomes

Do not present a case study as complete if it lacks substance.

---

## UI rules

- prioritize readability above all
- keep layouts simple and intentional
- maintain consistent spacing throughout
- use strong visual hierarchy
- support fast scanning
- design mobile-first
- avoid unnecessary motion
- avoid visual noise

The interface should feel:

- premium
- restrained
- balanced
- well-paced

Avoid:

- decorative animation without purpose
- forced line breaks in copy
- inconsistent card layouts
- crowded sections
- oversized text blocks
- abrupt spacing changes

---

## Interaction rules

- all CTAs must be real and functional
- no dead links
- no fake buttons
- no href="#" for real actions
- navigation must feel obvious
- hover and motion should be subtle and purposeful

Contact actions must always work:

- email
- LinkedIn
- CV / resume if included

---

## Content consistency rules

- use one editorial language only across the portfolio
- keep labels, headings, and CTA language consistent
- keep naming conventions consistent across all case studies
- do not mix temporary copy with final copy
- remove any placeholder text or generic imagery

---

## Code quality rules

- keep HTML semantic and clean
- avoid unnecessary wrappers
- use accessible markup
- keep CSS organized and scalable
- avoid hacks that hurt responsiveness
- prefer maintainable structure over quick fixes
- use JavaScript only when it adds clear value

Avoid:

- inline fixes that create inconsistency
- excessive DOM complexity
- layout decisions based on hardcoded line breaks
- interactions that reduce clarity on mobile

---

## Accessibility basics

Always check:

- heading structure
- alt text quality
- keyboard access for interactive elements
- visible focus states
- color contrast
- readable text sizes
- touch-friendly spacing on mobile

---

## Before finishing a task

Check:

- responsiveness
- accessibility basics
- visual hierarchy
- consistency with the portfolio tone
- clean HTML structure
- real and functional CTAs
- no placeholders
- no unnecessary animations
- strong scanability on mobile
